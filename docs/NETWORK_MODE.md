# UniTest — сетевой режим

## Назначение

Компьютер преподавателя запускает локальный сервер тестирования. Ученики подключаются через браузер по IP:порту или коду занятия. Клиентское приложение ученику не требуется.

Локальный сервер **не предназначен** для публикации в интернет «из коробки». Доступ — в пределах разрешённых интерфейсов/LAN. Для другой сети — VPN или отдельно настроенный внешний сервер.

## Сценарий проведения

1. Преподаватель открывает/создаёт тест.
2. Выбирает «Сетевое тестирование».
3. Настраивает параметры сессии.
4. Создаётся запись `sessions` со снимком `quiz_version_id`.
5. Система показывает реальные адреса прослушивания, порт и код.
6. Ученики открывают страницу join и вводят код (или полный URL).
7. Преподаватель видит участников.
8. Старт тестирования (`running`).
9. Ученики отвечают; ответы сохраняются идемпотентно.
10. Преподаватель наблюдает статусы (polling).
11. Ученик отправляет итог.
12. Преподаватель завершает/закрывает сессию.
13. Результаты в MySQL, доступен экспорт.

Кратковременный disconnect **не** завершает попытку. После reconnect восстанавливаются сохранённые ответы.

## Подключение

### По адресу

Пример: `http://192.168.1.25:8080` — иллюстрация; фактические адреса определяются на машине преподавателя (перечень IPv4 интерфейсов, исключая заведомо неподходящие).

### По коду занятия

- Случайный код, устойчивый к подбору (достаточная энтропия, не 4 цифры).
- Ограниченный срок действия / привязка к активной сессии.
- Rate limit на `/api/v1/join`.

Страница подключения не показывает административные токены.

## Статусы сессии

| status | Смысл |
|--------|--------|
| draft | создана, ещё не для учеников |
| open | регистрация открыта |
| running | тестирование идёт |
| paused | пауза (если режим поддерживается) |
| finished | завершено, результаты доступны |
| closed | закрыта окончательно |

## Статусы участника

`joined` → `in_progress` → `submitted`; отдельно `disconnected` при потере связи без завершения.

## API (черновик `/api/v1`)

Реализуются по мере этапов; фиктивных эндпоинтов без логики не создавать.

```text
POST   /api/v1/sessions
GET    /api/v1/sessions/{id}
POST   /api/v1/sessions/{id}/start
POST   /api/v1/sessions/{id}/finish
POST   /api/v1/sessions/{id}/close

POST   /api/v1/join
GET    /api/v1/participant/session

POST   /api/v1/attempts/start
POST   /api/v1/attempts/{id}/answers
POST   /api/v1/attempts/{id}/submit

GET    /api/v1/sessions/{id}/results
```

Правила:

- валидация входа;
- единый формат ошибок;
- проверка прав;
- идемпотентность ответов (`UNIQUE attempt_id + question_id`);
- учёт статуса сессии/попытки;
- **серверное время** авторитетно для дедлайнов;
- правильные ответы не в ответах API до разрешения.

Этап 5: периодический polling. WebSocket — опционально позже.

## Безопасность сети

- Bind на выбранные интерфейсы (конфиг), не «весь интернет» по умолчанию.
- CSRF для web-сессий преподавателя.
- Токен участника (cookie/header) с хешем в БД.
- Не доверять клиентскому score: пересчёт на сервере.

## UI панели сессии

Показывать: название теста, код, IP-адреса, QR ссылки (если есть библиотека), список участников и статусы, кнопки старт/пауза/завершение, прогресс, результаты. Без секретных admin-токенов в публичной зоне.
